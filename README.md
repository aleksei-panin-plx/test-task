# CardForge

CardForge делает коллекции игровых карточек-предметов в стиле игры: коллекция — 16 сетов по 10 карт на одну
тему («Лето», «Кино», «Путешествие»). Гейм-дизайнер работает в своём агенте (Claude Code или Codex): называет
тему коллекции и, если нужно, число сетов, правит план (G1), проверяет готовые сеты (G3) и получает PNG.
Картинки рисует GPT Image 2.5 через OpenRouter; стиль, рамку, надписи и обрезку проверяют судьи и локальные
проверки ядра. Версия 0.0.1.

## Что где лежит

| Папка | Для кого | Что внутри |
|---|---|---|
| [`cardforge/`](cardforge/) | гейм-дизайнер на своём компьютере | ядро CardForge, локальный плагин для Claude Code и Codex (MCP по stdio), установщик одним действием (macOS: двойной щелчок по `installer/install.command`) |
| [`cardforge-server/`](cardforge-server/) | администратор сервера | сервер: MCP по Streamable HTTP с теми же 18 инструментами, очередь прогонов, личные ключи, страницы гейтов в браузере, месячный лимит на пользователя, учёт использования, хранение прогонов |

Обе папки **автономны**: в каждой своя полная копия ядра (`src/cardforge/`, `knowledge/`, `policies/`,
`prompts/`, `config/`, общие тесты `tests/`), ни одна не зависит от другой как от пакета. Копии одинаковы,
кроме намеренных расхождений из [`cardforge-server/core-sync.toml`](cardforge-server/core-sync.toml) (сервер
разрешает план от агента пользователя, рабочая папка `/srv/cardforge`). Правка ядра делается в папке 1 и
переносится на сервер только скриптом:

```bash
python -I cardforge-server/scripts/sync_core.py cardforge cardforge-server
```

Отчёт последней синхронизации с sha256 ядра — [`cardforge-server/docs/core-sync.md`](cardforge-server/docs/core-sync.md).

## Что не входит в репозиторий

| Что | Почему | Откуда берётся |
|---|---|---|
| архив данных заказчика `cardforge-data-0.0.1.tar.gz` (≈ 630 МБ: референсы игры `dataset/`, картинки рамки `knowledge/frames/*.png`, свидетельства ревью масок) и папка `cardforge/assets/` | материалы заказчика не публикуются | команда CardForge передаёт из рук в руки (флешка, файловый сервер компании); установщик берёт архив из `cardforge/assets/` или по `--data <архив>`, сервер — распакованным рядом с кодом или в `./data` |
| веса моделей (u2net ≈ 176 МБ, CSD ViT-L ≈ 2,3 ГБ) | размер | установщик и `cardforge fetch-assets` скачивают их сами по `models/*/source.json` со сверкой sha256 |
| `runs/`, `.env`, `.venv`, кэши | локальное состояние и ключи | создаются при работе; ключ OpenRouter — только в окружении или `.env` |
| `*.private*`, `labels.private/` | приватные метки людей | не распространяются |

Ручная разметка в `knowledge/` (`human_review.jsonl`, `disagreements*`, `human_feedback_v1.json`, `reviews/`)
и локальные пути в коде и тестах опубликованы как есть — по явному решению владельца репозитория.

## Что проверено, что нет

| | Статус |
|---|---|
| тесты ядра и плагина в папке 1 (FakeBackend, без сети) | зелёные |
| тесты ядра и сервера в папке 2, e2e через MCP HTTP на FakeBackend | зелёные |
| установщик macOS: `install.sh --dry-run` в тесте, сборка папки 1, `uv sync --frozen`, `doctor` | проверено |
| установка на чистом Mac человеком | не подтверждено |
| **Windows** (`install.bat` / `install.ps1`, RapidOCR, CPU-torch) | **не проверено**: ни разу не запускалось на Windows |
| **Docker**: образ сервера и запуск в Linux-контейнере | **не проверено**: образ не собирался |
| **платный тест чистого листа** (живой прогон коллекции через плагин до выдачи) | **не проводился**: нужно отдельное разрешение |
| **Codex вживую**: установка плагина и старт MCP-сервера | проверено; разговор с агентом и рендер — **нет** |
| подключение агента к живому серверу, платный прогон через сервер | не проверено |
| развёртывание сервера и сервис AI Portal | не входит в этот репозиторий, ничего не развёрнуто |
